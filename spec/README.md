# SongHub Feature Requirements Specification

This directory contains product-level feature requirements for upcoming SongHub capabilities.

Purpose:
- Define what must be built.
- Define expected user behavior and system behavior.
- Define acceptance criteria and phased delivery.
- Define unambiguous decision rules for permissions and ownership behavior.

Out of scope for this specification:
- Implementation details
- Internal architecture decisions
- Source code references
- Technology-specific instructions

Specification conventions:
- Every requirement uses a stable requirement ID.
- Requirement IDs are normative and testable.
- If two requirements appear to conflict, precedence rules in 05-glossary-and-decision-rules.md apply.

Documents:
1. `01-product-scope.md` - vision, goals, user roles, and core feature boundaries
2. `02-acl-and-sharing.md` - access control, group ownership, and sharing requirements
3. `03-song-page-tabs-notes-links.md` - song page, tabs, notes, links, and copy workflow requirements
4. `04-delivery-phases-and-acceptance.md` - milestones, definition of done, and verification requirements
5. `05-glossary-and-decision-rules.md` - domain glossary, permission precedence, and conflict resolution rules
6. `06-edge-cases-open-questions-risks.md` - lifecycle edge cases, open questions, assumptions, and risk controls
